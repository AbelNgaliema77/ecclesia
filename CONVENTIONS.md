# Conventions

## Code

- TypeScript strict with noUncheckedIndexedAccess. No any, no non-null assertions.
- No comments in production code. Names carry the meaning; anything that needs explaining goes in an ADR.
- Named exports only, except where Next.js requires a default export (pages, layouts, route config).
- Files are kebab-case. Components are PascalCase. Functions and variables are camelCase.
- Prefer small pure functions over classes. The only class in the app is ActionFailure.
- Import types with import type.
- Biome formats and lints everything. Do not hand-format.

## Where code goes

| You are adding                 | Put it in                                           |
| ------------------------------ | --------------------------------------------------- |
| A business rule or calculation | packages/domain/src/<module> with a test next to it |
| A database query               | packages/db/src/repositories/<module>.ts            |
| A table or column              | packages/db/src/schema, then pnpm db:generate       |
| A server action                | apps/web/src/modules/<module>/actions.ts            |
| Page data loading              | apps/web/src/modules/<module>/queries.ts            |
| A feature component            | apps/web/src/modules/<module>/                      |
| A reusable UI primitive        | apps/web/src/components/ui/                         |
| A route                        | apps/web/src/app/ – keep pages thin                 |

Modules do not import each other's internals. Shared needs move down into domain or db.

## Server actions

- Signature: (previousState, formData) => Promise<ActionState<T>>, used with useActionState.
- Always wrap the body in runChurchAction({ permission, write }).
- Validate with parseInput(schema, formToObject(formData)). Use ensure for permission and existence checks, unwrap for domain Results.
- Record an audit entry for every write, then revalidatePath the affected routes.
- Return error codes, never translated text. The client translates codes from errors.* in the messages files.

## Database

- Tables are plural snake_case. Columns are snake_case in SQL and camelCase in TypeScript (Drizzle casing handles it).
- Ids are UUIDs generated by Postgres. Timestamps are timestamptz. Dates without time use date.
- Every church-owned table: id, church_id, created_at, updated_at, plus unique (church_id, id).
- Localised labels are jsonb { en, fr }.

## UI

- Sentence case for all text. No all-caps labels.
- Buttons say what they do: "Save person", "Open headcount", not "Submit".
- Errors say what happened and how to fix it. Empty states say what to do next.
- Use the design tokens in globals.css. Do not introduce new colours or fonts without updating them there, in both light and dark.
- Successful saves confirm with a toast. Errors stay inline next to the form.
- Every screen must work at 390px with the bottom tab bar, and in dark mode.
- Dates and numbers go through next-intl formatters, never toString or manual formatting.
- En dashes (–) in copy, not em dashes.

## Git

- Branch from main. One feature or fix per branch.
- Commit messages and PR titles are plain sentences, for example "Add headcount corrections to attendance". No type prefixes.
- PR descriptions are bullet points: what changed, how it was tested, anything the reviewer should look at.
